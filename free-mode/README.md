# 自由创作模式（free-mode）

> 库内**第三模式**。与「动效模式」「学术模式」并列，但**完全隔离**：
> 产物与数据不回流到其他模式，其他模式也不读取本模式的任何内容。

## 一、能做什么

| # | 能力 | 做法 |
|---|---|---|
| 1 | **改** 现有效果 | 从 `effects/`（动效类）或 `effects/academic/`（学术类）**复制一份参考件**到工作区，再改配色 / 版式 / 文本 / 文框 / 图片 / 标题 |
| 2 | **拼** 多个效果 | 复制多份参考件，按页重组；也可把用户自己的 PPT 并进来一起拼 |
| 3 | **搭** 从零做页 | 用库里的工具 + 参考件素材（形状、样式集、配色、版式骨架）从空白页搭 |

可复用的素材与工具：

| 来源 | 可用内容 |
|---|---|
| `effects/001–017` | 17 个动效参考件 |
| `effects/academic/` | 学术导航0（20 页）、学术模板1（六套 × 23 页） |
| `layout-tools/` | 22 页原生版式骨架 |
| `text-tools/` | 标题 100 / 导航 40 / 文框 50 种样式集 |
| `image-tools/` | 取景形状（cut/circle/hex/arch/diag/capsule…）、custGeom 校验 |
| `palette-tools/` | 11 套配色 + `recolor` 系列工具 |
| `template-tools/` | 模板占位化与填充 |

## 一·五、从学术模式分流过来（2026-11-15 起）

学术模式下，用户若提出**改版式 / 改标题 / 改导航 / 改文框**等结构改动，
不在学术模式里原地改，而是：

1. 说明"这属于自由创作"
2. 转入本模式
3. **复制一份**用户要改的那份 PPT（或用户指定的一份）作为创作修改件
4. 原件不动，成品按本模式规则处理

## 二、三条硬规则

### 规则 1 · 库内不存草稿

- 草稿一律放**工作区**：`<USER_HOME>\Documents\<DSH_HOME>\default-workspace\free\`
- 库内**不保存**任何"未定稿"或"已放弃"的中间文件
- 用户说**「放弃」或「认可」**时，必须问：
  1. 是否保存？
  2. 保存在哪个路径？
- 只有明确"保存"才落盘；明确"放弃"则删除工作区草稿

### 规则 2 · 完全隔离

| 隔离项 | 要求 |
|---|---|
| 产物 | 不写入 `effects/`、`templates/`、`*-tools/` |
| 数据 | 不回流（不改配色库、不改样式集、不改参考件） |
| 索引 | 不登记到 `index.md` 的效果目录 |
| 复用 | 只能**复制**参考件，不改原件 |

### 规则 3 · 可调用外部插件，但先确认兼容

- 允许调用 `ppt-master` 或用户自行安装的插件
- **调用前必须与用户确认**：插件名称、版本、与本库的兼容性风险
- 兼容性未确认前，不得擅自用插件覆盖库内参考件

## 三、工作区约定

```
default-workspace\free\
└─ <日期>-<主题>\
    ├─ draft\        过程稿（可随时删）
    ├─ assets\       从库里复制的参考件、素材
    ├─ out\          成品（用户认可后才往桌面/指定路径落）
    └─ notes.md      改了什么、拼了哪几份、用了哪些工具
```

## 三·五、工具：free_kit.py（2026-11-18）

> **与工作台 `pm_*` 的分工**（详见 workbench `docs/WORKFLOW.md` §4.1）：
> `pm_*` 管**改结构与质检**（SVG 拆合、模板套用、形状/布尔、文本测量、交付检查）；
> `free_kit` 管**素材与页级装配**（取件、改色、取景 PNG、填充、拼接、放图、批量改字、预览）。
> 动效/学术模式不改用 `free_kit` 动参考件；自由创作不拿 `pm_*` 覆盖库内参考件。

`free-mode/free_kit.py` 把本模式的重复动作固定下来：

| 命令 | 作用 |
|---|---|
| `new <主题>` | 建 `default-workspace\free\<日期>-<主题>\{draft,assets,out}` + `notes.md` 模板 |
| `add <工作区> <效果号>` | 把该效果的参考件**复制**进 `assets/`（不碰原件） |
| `recolor <工作区> <文件> <配色>` | 按 `palette-tools/palettes.json` 重新上色，输出到 `out/` |
| `shape <图片> <形状> [宽 高]` | 调 `image-tools/mask_lib` 生成形状遮罩 PNG（10 种形状） |
| `fill <工作区> <模板> <内容.json>` | 按占位名批量填文字/图片（复用 `template-tools/fill_template.py`） |
| `merge <工作区> <目标> [源[:页,页] ...] [--fix-seams]` | **跨文件拼接**：把多份参考件的页并进同一份（PowerPoint COM，属已批准例外）。**每次都会做接缝自检并打印风险提示**；加 `--fix-seams` 把退化的 morph 改成淡入 |
| `place <工作区> <目标> <页> <图片> [x y w [h]]` | 把图片放到指定页（cm 坐标） |
| `text <文件> <old=new> [...] [--no-fit]` | 批量替换文字（整段精确匹配，兼容被拆成多个 run 的文本）；**放不下会自动按比例缩字号**（只动改过的框，最低 9pt / 最多缩到 30%），`--no-fit` 关闭 |
| `render <文件> [页,页] [--out 目录]` | 导出指定页 PNG 并拼一张对照图，验证用 |
| `list` | 列可用效果源与 11 套配色 |

示例：

```bash
python free-mode/free_kit.py new 述职-蓝
python free-mode/free_kit.py add <工作区> 011
python free-mode/free_kit.py recolor <工作区> 效果11.pptx 学术蓝
```

### 改色前先看 `color_source`

每个 `spec.json` 都有 `color_source`，由**实测像素差**判定：

| 取值 | 含义 | 改色效果 |
|---|---|---|
| `srgb` | 颜色多为直写 `srgbClr` | ✅ 可用 |
| `theme` | 颜色由主题色驱动（改 `clrScheme`） | ✅ 可用 |
| `image` | 主体颜色来自图片（照片/素材） | ❌ 基本无效 |

当前分布：`theme` 6 个、`srgb` 2 个、`image` **9 个**（17 个效果里过半是图驱动的）。

`free_kit` 会按参考件文件名反查 spec，`image` 类直接拦截并提示换图/换效果；
确需强行尝试时加 `--force`。

> 改色的已知副作用：整体改色无法区分“装饰色”和“语义色”，
> 像效果9 的图例圆点会跟着变色，改完需要人工看一眼。

## 四、与其他模式的关系

| 模式 | 入口 | 产物去向 |
|---|---|---|
| 动效模式 | 「PPT启动」→ ①动效 | 库内效果，或桌面成品 |
| 学术模式 | 「PPT启动」→ ②学术 | 库内模板，或桌面成品 |
| **自由创作模式** | 「PPT启动」→ ③自由创作 | **只到用户指定路径**，库内不留 |

> 进入本模式后，不再走学术模式的"选色 → 选版式"固定流程；
> 而是按用户的创作意图自由取材，但仍遵守本文件的隔离与保存规则。
