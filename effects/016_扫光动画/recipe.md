# 效果16 · 扫光动画（DeepSeek Harness）

**基准件**：`reference/效果16.pptx`（1 页，51 KB）
**方式**：`template-clone` —— **只改文案，不动形状与动画**

## 为什么只能改文字

单页里塞了 **31 个形状 + 99 个动画节点**（fade / wipe / 位移 / 缩放混排），重做成本极高，而且原件的时序是人工反复调出来的，重建一定跑偏。所以这条效果的使用原则：

> **允许改：文字内容、字号、颜色。**
> **禁止改：形状、位置、尺寸、层级、动画时序。**

改文案时的注意点：

1. **字号可以调，但字数要控制**——文本框是定宽的，字号变大或字数变多都会换行，挤乱动画落点；改完必须逐页确认没有回行
2. 大字（DeepSeek / Harness / 我是大肥鱼）换成别的词时，留意字号是否还合适
3. `DeepSeek` 出现在 id 4 和 id 7 两个文本框，**是同字叠放做动画**，要改就两处一起改，否则错位

## 换文案的安全做法

```
1. 复制 reference/效果16.pptx
2. 只改 <a:t> 里的文字，不动 <a:rPr> 的字号/字体，不动 <p:timing>
3. 保存后必须 F5 播一遍，确认文字没有超出框、没有挡到别的元素
```

不要用 python-pptx 重建文本框（会丢动画绑定），改现有 `a:t` 文本节点即可。

## 调用时要问

按用户规则，改文案前必须确认：

- 每段文字的新内容（11 处，或只改其中几处）
- 字号是否沿用
- 是否要保留 `DeepSeek` 双份叠放的结构

## 坑

1. **动画按 id 绑定**：删形状、重建文本框会让动画失效
2. **文字超框**会导致换行，位移落点算的是原文字宽度，会错位
3. 关键帧多（99 个 par），**改了形状就几乎不可能修回**，这是“只改文案”的根本原因
4. 本地渲染只能看静帧，动画必须在 PowerPoint 里播

## 允许的修改范围（2026-11-13 更新）

| 项 | 可改 | 说明 |
|---|---|---|
| 文字内容 | ✅ | 字数尽量接近原文 |
| 字号 | ✅ | 放大要留意文本框宽度，别回行 |
| 颜色 | ✅ | 改 :solidFill 里的颜色值即可 |
| 字体 | ⚠️ 谨慎 | 换字体可能改变字宽，导致回行 |
| 形状 / 位置 / 尺寸 / 层级 | ❌ | 会破坏动画落点 |
| 动画时序 | ❌ | 99 个 par，动了几乎修不回 |

## 实测案例（食堂版，未入库）

把 17 处文字换成食堂主题后，99 个动画节点完好，播放正常。经验：

1. **中文换中文很安全**，只要字数接近
2. **英文换英文要格外小心**：Harness → CANTEEN 会换行（CANTEEN 更宽）
   - 处理办法有三种，优先用前两种：
     a. **保留首字母大写**（Canteen 比 CANTEEN 窄，仍可能放不下，需配合 b）
     b. **字号略缩**：把该 run 的 :rPr sz 减 4–8pt（如 8000 → 7200），通常就能单行放下
     c. 换成更短的词（如 MENU）——观感上最稳，但可能改变原意

   > 实测：Canteen 在 72pt（sz=7200）下**单行放得下**，已录像确认；CANTEEN 在 80pt 会换行。
3. 长句缩短比加长安全：在这里你不仅可以写代码，跑测试 → 在这里能吃到现炒热菜，还有汤 正好不换行
4. DeepSeek 两处叠放必须同时改，否则扫光时错位

## 字数与字号上限（实测）

大字文本（原「推理」166pt，文本框宽 13.13cm）能放几个字：

| 字数 | 最大字号 | 说明 |
|---|---|---|
| 2 字 | 166pt 可用 | 约 11.7cm |
| 3 字 | **≤112pt** | 112pt 时约 11.9cm，单行稳妥；166pt 会到 17.6cm 换行 |

经验公式：字号(pt) × 0.0353 × 字数 ≤ 文本框宽度(cm)

同理：
- Harness(80pt) 文本框较宽，可放 6–7 个字母；CANTEEN 7 字母会换行 → 缩到 72pt 或换短词
- 长句（44pt、宽 24–28cm）约 18–20 个汉字，超出必换行
